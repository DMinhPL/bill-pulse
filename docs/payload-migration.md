# Moving BillPulse75 to Next.js and Payload CMS

This guide moves BillPulse75 from Express and hand-written SQL to a single Next.js app with Payload CMS 3. Payload becomes the database layer and the admin panel for content such as bill categories, AI prompts, lookups and sample bills.

## Decisions already made

| # | Decision |
|---|----------|
| 1 | **One Next.js app.** Payload, the admin panel, the API and the React app live in the same project and deploy together to Vercel. |
| 2 | **Two auth collections.** `admins` sign in to the admin panel. `users` are app accounts and can never open the admin panel. |
| 6 | **The admin panel is not at `/admin`.** It lives at `/bp-management` (see 1.6). `/admin` returns 404. |
| 3 | **Receipt files are not stored**, as today. There is no upload collection and no storage adapter. |
| 4 | **The SQL views `item_price_history` and `product_price_trends` are dropped.** Price trends stay in the browser (`computePriceHistoryMap`). |
| 5 | **Existing passwords are migrated with a legacy-hash fallback.** Users keep their passwords and are re-hashed by Payload on their first login. |

## Ground rules

- Work on a branch, for example `feat/payload`. Merge to `main` only after Phase 5.
- Every phase ends with a **Done when** check. Don't start the next phase until it passes.
- The legacy database is **read-only** during the whole migration. Payload gets a new Neon branch or database.
- Keep the frontend's data shapes (`Bill`, `BillItem`, `AuthUser`) unchanged. All conversion happens on the server in `billDto.ts`, so components don't need changes.
- `shared/` must not import from `client/` or `payload/`. Server code must not import from `client/`.

### Why the app API lives under `/api/app/*`

Payload's REST API takes `/api/<collection-slug>/*` (for example `/api/bills`, `/api/users`), and the admin panel relies on it. The app's own routes go under `/api/app/` so they never collide with Payload. Next.js matches a static segment (`api/app/...`) before Payload's catch-all (`api/[...slug]`). In `src/client/utils/api.ts`, only the URL prefix changes.

### 1.6 Hidden admin path

Payload serves its admin panel from a Next.js folder, and `routes.admin` in the config tells Payload where that folder is. Both must use the same path. Next.js folder names are fixed at build time, so the path is committed to the repo; it can't come from an environment variable.

1. **The slug is `bp-management`**, so the admin panel lives at `/bp-management`. It's readable and easy for admins to remember, but it can be guessed (it follows the app's `bp` prefix and names its purpose). That's fine as long as the protections listed after these steps are in place; they don't depend on the path staying secret.

2. **Keep it in one constant**, `src/payload/adminRoute.ts`:

   ```ts
   /** Path of the Payload admin panel. Must match the folder src/app/(payload)/bp-management/. */
   export const ADMIN_ROUTE = '/bp-management';
   ```

3. **Rename the folder**: `src/app/(payload)/admin/` → `src/app/(payload)/bp-management/`. Leave the files inside (`[[...segments]]/page.tsx`, `not-found.tsx`) unchanged.

4. **Point the config at it**: `routes: { admin: ADMIN_ROUTE }` (already in the 1.4 snippet). Then run `pnpm generate:importmap`.

5. **Check that `/admin` is gone.** It isn't in `ROUTE_PATTERNS`, so the frontend catch-all already returns the app's 404 page for it. Don't add a redirect from `/admin`.

6. **Keep the slug out of public places:**
   - No link to it in the app, `README.md`, `robots.txt` or `sitemap`. Share it with admins privately.
   - Don't add it to `robots.txt` as `Disallow`, because that file is public and would publish the path.
   - Tell search engines not to index it, in `next.config.ts`:

     ```ts
     import { ADMIN_ROUTE } from './src/payload/adminRoute';

     const nextConfig: NextConfig = {
       async headers() {
         return [{ source: `${ADMIN_ROUTE}/:path*`, headers: [{ key: 'X-Robots-Tag', value: 'noindex, nofollow' }] }];
       },
     };
     ```

A non-default path only cuts down on bots that scan for `/admin`. It is **not** access control: the login endpoint stays at `/api/admins/login` whatever the slug is, and the path can leak through browser history, screen shares or logs. So also do the following:

- **Lock out brute force** on `admins`: `auth: { maxLoginAttempts: 5, lockTime: 15 * 60 * 1000 }`.
- **Turn off public admin sign-up**: keep `create: isAdmin` on `admins`. Payload only shows its "create first admin" screen while `admins` is empty, so create the first admin locally or right after the first deploy, before sharing the URL.
- **Optional, stronger:** add a `src/middleware.ts` that returns 404 for `${ADMIN_ROUTE}/*` and `/api/admins/*` unless the request comes from an allowed IP (`ADMIN_ALLOWED_IPS` env) or carries Basic Auth credentials (`ADMIN_BASIC_AUTH` env). This works without changing the slug, and you can turn it on later.
- **GraphQL:** keep `graphQL.disablePlaygroundInProduction` at its default (`true`), so the playground doesn't show the schema in production.

**Changing the slug later:** rename the folder, update `ADMIN_ROUTE`, run `pnpm generate:importmap`, and redeploy. Admins have to sign in again only if their cookie path changes, which it doesn't (the cookie path is `/`).

**Done when:** `pnpm dev:next` serves every page at the same URLs, unknown URLs (including `/admin`) show the 404 page, `/bp-management` lets you create the first admin, and Tailwind styles look identical. API calls can still fail at this point.

### 2.1 Access helpers (`src/payload/access/`)

```ts
// isAdmin.ts
import type { Access } from 'payload';
export const isAdmin: Access = ({ req }) => req.user?.collection === 'admins';

// isOwnerOrAdmin.ts
export const isOwnerOrAdmin: Access = ({ req }) => {
  if (req.user?.collection === 'admins') return true;
  if (req.user?.collection === 'users') return { user: { equals: req.user.id } };
  return false;
};
```

### 2.3 `users` (app accounts)

```ts
export const Users: CollectionConfig = {
  slug: 'users',
  auth: {
    loginWithUsername: { allowEmailLogin: false, requireEmail: true },
    tokenExpiration: 60 * 60 * 24 * 30, // 30 days, same as SESSION_DAYS today
    cookies: { sameSite: 'Lax', secure: process.env.NODE_ENV === 'production' },
  },
  admin: { useAsTitle: 'username', group: 'Accounts' },
  access: {
    admin: () => false, // app users can never open the admin panel
    read: ({ req }) =>
      req.user?.collection === 'admins' ? true :
      req.user?.collection === 'users' ? { id: { equals: req.user.id } } : false,
    create: isAdmin,  // public sign-up goes through /api/app/auth/register only
    update: ({ req }) =>
      req.user?.collection === 'admins' ? true :
      req.user?.collection === 'users' ? { id: { equals: req.user.id } } : false,
    delete: isAdmin,
  },
  hooks: { afterChange: [seedSampleBills] },
  fields: [
    { name: 'displayName', type: 'text', required: true, maxLength: 80 },
    {
      // scrypt$<salt>$<hash> from the old database; cleared after the first successful login
      name: 'legacyPasswordHash',
      type: 'text',
      hidden: true,
      access: { read: () => false, update: () => false },
    },
  ],
};
```

- Payload adds the `username` and `email` fields itself. Add a `beforeValidate` field hook to `username` that enforces today's `USERNAME_RE` (`^[a-zA-Z0-9._-]{3,32}$`) and its Vietnamese error message.
- Usernames are case-insensitive today (`lower(username)` unique index). Store usernames **lowercased** (field `beforeValidate` hook) and lowercase the input on login. `displayName` keeps the casing the user typed.

### 2.4 Shared bill fields (`src/payload/fields/billFields.ts`)

Used by both `bills` and `sample-bills`:

| Field | Type | Notes |
|---|---|---|
| `merchantName` | text, required | default `'Không rõ cửa hàng'` |
| `branch`, `billNumber` | text | |
| `date` | text, required | `YYYY-MM-DD`, checked with a regex in `validate`. Text avoids timezone shifts on a `date` field |
| `time` | text | `HH:mm` regex |
| `category` | text, required | `validate` checks the key exists in `bill-categories` |
| `paymentMethod` | text | |
| `subtotal`, `discountTotal`, `vat`, `totalAmount` | number, `min: 0` | whole VND |
| `confidenceNotes`, `fileName` | text | |
| `fileType` | select `image` / `pdf` | |
| `items` | array | see below |

Each row of `items` has: `rawName`, `canonicalName`, `unit` (text), `quantity` (number, `min: 0.001`), `unitPrice`, `totalPrice`, `discount` (number, `min: 0`), `category` (text), `product` (relationship → `products`, read-only in the admin panel). Payload gives every row an `id` and keeps the order, which replaces `line_no`.

### 2.5 `bills`

```ts
export const Bills: CollectionConfig = {
  slug: 'bills',
  admin: { useAsTitle: 'merchantName', defaultColumns: ['merchantName', 'date', 'totalAmount', 'user'], group: 'Data' },
  access: { read: isOwnerOrAdmin, update: isOwnerOrAdmin, delete: isOwnerOrAdmin, create: ({ req }) => !!req.user },
  hooks: { beforeChange: [normalizeBill, linkProducts] },
  fields: [
    { name: 'user', type: 'relationship', relationTo: 'users', required: true, index: true },
    ...billFields,
  ],
  indexes: [{ fields: ['user', 'date'] }],
};
```

- `normalizeBill` (beforeChange): takes over the cleanup from `insertBill()` in `server/bills.ts`. It rounds VND amounts and clamps them at 0, falls back to today's date, drops an invalid time, sets `category` to `'Other'` when the key is unknown, works out `fileType` from `fileName`, and defaults `quantity` to 1 and `unit` to `'cái'`. When the caller is a `users` account, it forces `data.user = req.user.id`, so a client can never save a bill for someone else.
- `linkProducts` (beforeChange): for each item, find the product by `normalizedKey = normalizeItemKey(canonicalName)` and create it if it's missing. Always pass `req` so it runs in the same transaction. If the create fails on the unique index (two saves at once), look the product up again.

### 2.6 `products`

Fields: `canonicalName` (text, required), `normalizedKey` (text, required, `unique: true`, `index: true`, read-only in the admin panel), `unit` (default `'cái'`), `category` (default `'Hàng tiêu dùng'`).
Access: everyone signed in can read, only admins can write (the hook writes with `req`, which runs as the saving user, so call `req.payload.create` with `overrideAccess: true` inside `linkProducts`).

### 2.7 `bill-categories`

Fields: `key` (text, unique, e.g. `Supermarket`), `label` (Vietnamese label), `order` (number).
Access: public read, admin write. Seeded with today's seven keys, so the three hard-coded copies (TS union, SQL `CHECK`, prompt) collapse into this one.

> Keep the `Bill['category']` TS type as `string` from now on, and use the bootstrap data (see 3.4) for the list.

### 2.8 `sample-bills`

Same `billFields`, no `user` field. Admin-only access. The admin panel can edit which bills new accounts start with.

`seedSampleBills` (afterChange on `users`):

```ts
export const seedSampleBills: CollectionAfterChangeHook = async ({ doc, operation, req, context }) => {
  if (operation !== 'create' || context.skipSeed) return doc;
  const { docs } = await req.payload.find({ collection: 'sample-bills', pagination: false, depth: 0, req });

    await req.payload.create({ collection: 'bills', data: { ...bill, user: doc.id }, req, overrideAccess: true });
  }
  return doc;
};
```

## Phase 3: App API and the frontend switch

### 3.1 Server helpers (`src/server/`)

`payload.ts`:

```ts
import { getPayload } from 'payload';
import config from '@payload-config';
import { headers } from 'next/headers';

export const payload = () => getPayload({ config });

/** The signed-in app user, or null. Admin sessions don't count as app users. */
export async function currentUser() {
  const p = await payload();
  const { user } = await p.auth({ headers: await headers() });
  return user?.collection === 'users' ? user : null;
}
```

`billDto.ts` has two functions:

- `toBill(doc)` turns a Payload bill into today's `Bill` shape. It maps `items[].id`, drops `user`, `product` and `updatedAt`, and keeps `createdAt`.
- `fromBill(body)` picks only the known `Bill` fields from a request body and ignores any `id`. It is the same allow-list `insertBill()` uses today.

`http.ts`: `json(data, status)` and `errorJson(message, status)`, which return `{ error }` the way the client expects.

### 3.2 Route handlers

Every handler that needs a user starts like this:

```ts
const user = await currentUser();
if (!user) return errorJson('Vui lòng đăng nhập.', 401);
```

| Route | Implementation |
|---|---|
| `POST /api/app/auth/register` | Validate exactly like `server/auth.ts` (same messages). Check that username and email are free (409 with which one is taken). Then `payload.create({ collection: 'users', data: { username, email, displayName, password } })`, which seeds sample bills via the hook. Then log in (below) and return `{ user }` with status 201. |
| `POST /api/app/auth/login` | See 3.3 (legacy-hash fallback). |
| `POST /api/app/auth/logout` | Clear the `${payload.config.cookiePrefix}-token` cookie and return `{ success: true }`. |
| `GET /api/app/auth/me` | `currentUser()` → `{ user: { id, username, email, displayName } }`, otherwise 401. |
| `GET /api/app/bills` | `payload.find({ collection: 'bills', where: { user: { equals: user.id } }, sort: ['-date', '-createdAt'], pagination: false, depth: 0, user, overrideAccess: false })` → `{ bills: docs.map(toBill) }` |
| `POST /api/app/bills` | `payload.create({ collection: 'bills', data: { ...fromBill(body), user: user.id }, user, overrideAccess: false })` → `{ bill }`, 201 |
| `DELETE /api/app/bills/[id]` | `payload.delete({ collection: 'bills', id, user, overrideAccess: false })`; NotFound or Forbidden → 404 `'Không tìm thấy hóa đơn.'` |
| `POST /api/app/bills/reset-sample` | In one transaction: delete the user's bills, then copy `sample-bills` (same code as the hook). Return the new list. |
| `POST /api/app/scan-bill` | Move the validation and response cleanup from `server/app.ts` unchanged. `gemini.ts` builds the prompt from `ai-settings` + `lookups` + `bill-categories`. Add `export const maxDuration = 60`. |
| `POST /api/app/analyze-inflation` | Same, using `inflationPrompt` and `inflationMaxItems`. `maxDuration = 60`. |
| `GET /api/app/bootstrap` | Public. Returns `{ billCategories, lookups }`. |
| `GET /api/app/health` | `{ status: 'ok', timestamp }` |

Transactions in route handlers (needed for reset-sample and register):

```ts
import { createLocalReq, initTransaction, commitTransaction, killTransaction } from 'payload';

const req = await createLocalReq({ user }, p);
await initTransaction(req);
try {
  // ...every Local API call gets `req`
  await commitTransaction(req);
} catch (err) {
  await killTransaction(req);
  throw err;
}
```

**Body size:** the 4 MB Express limit and its 413 handler go away. Keep the decoded-size check against `MAX_BILL_FILE_SIZE_BYTES` in `scan-bill`. Vercel still rejects bodies over 4.5 MB on its own.

### 3.3 Login with legacy-hash fallback (decision 5)

`src/server/legacyPassword.ts` holds `verifyPassword()` copied unchanged from `server/auth.ts` (scrypt + `timingSafeEqual`).

`POST /api/app/auth/login`:

1. Read `username` (lowercased) and `password`.
2. Try `payload.login({ collection: 'users', data: { username, password } })`.
3. If that throws an authentication error, look the user up by username with `overrideAccess: true` and `showHiddenFields: true`.
   - If `legacyPasswordHash` is set **and** `verifyPassword(password, legacyPasswordHash)` is true: call `payload.update({ collection: 'users', id, data: { password, legacyPasswordHash: null }, overrideAccess: true })`, then repeat step 2.
   - Otherwise return 401 `'Tên đăng nhập hoặc mật khẩu không đúng.'`
4. On success, set the auth cookie and return `{ user }`:

   ```ts
   const { token, exp, user } = await p.login(...);
   (await cookies()).set(`${p.config.cookiePrefix}-token`, token!, {
     httpOnly: true,
     sameSite: 'lax',
     secure: process.env.NODE_ENV === 'production',
     path: '/',
     expires: new Date(exp! * 1000),
   });
   ```

5. Use the same failure message for every failure, so the response never reveals whether a username exists.

Payload counts failed logins. Leave `maxLoginAttempts` at its default, or set it on `users.auth`, since the old app had no lockout.

### 3.4 Frontend changes (keep them small)

- `src/client/utils/api.ts`: add `const API = '/api/app'` and prefix every URL with it. Nothing else changes.
- `AuthUser.id` changes from `number` to `string` (UUID). Update its type and `loadedForUserId` in `AppDataContext.tsx`.
- `AppDataContext` fetches `/api/app/bootstrap` once and exposes `billCategories` and `lookups`. Replace the hard-coded category lists in `stagedBill.ts`, the scanner forms and the category views with this data.
- Sample bills in `QuickDemoBills` keep using `shared/seed/sampleBills.ts`, since they are demo scan results and not account data.

## Phase 4: Data migration (`scripts/migrate-legacy.ts`)

Run with `payload run scripts/migrate-legacy.ts`. It reads the old database with `pg` (`LEGACY_DATABASE_URL`) and writes through the Payload Local API. Order:

1. **Products:** create each with `canonicalName`, `normalizedKey`, `unit`, `category`. Keep a map from old numeric `id` to new UUID.
2. **Users:** for each row in `users`:

   ```ts
   await payload.create({
     collection: 'users',
     data: {
       username: row.username.toLowerCase(),
       email: row.email,
       displayName: row.display_name,
       password: crypto.randomBytes(32).toString('hex'), // never used; the legacy hash is checked instead
       legacyPasswordHash: row.password_hash,
     },
     overrideAccess: true,
     context: { skipSeed: true }, // don't add sample bills to migrated accounts
   });
   ```

   Keep a map from old user id to new UUID.
3. **Bills:** for each bill, load its `bill_items` ordered by `line_no` and create the bill with `id` = the old UUID text, `createdAt` = the old `created_at`, `user` = the mapped id, and `items[].product` = the mapped product id. Pass `context: { skipNormalize: true }` and let `normalizeBill` / `linkProducts` return early on that flag, so stored data is copied as-is.
4. **Skip:** `sessions` (everyone signs in once after cutover) and the two views.
5. Print counts for both sides and exit with an error if they differ.

Make the script re-runnable: skip a row if its `normalizedKey`, `username` or bill `id` already exists.

**Checks after the run:**

- Row counts match for users, products, bills and bill items.
- For three real accounts, the old and new `GET bills` responses are identical after sorting (ignoring item `id`).
- An old account can log in with its old password, and afterwards `legacyPasswordHash` is empty.
- A wrong password still fails.

**Done when** all checks pass on a copy of production data.

## Risks and how to handle them

| Risk | Mitigation |
|---|---|
| TypeScript 7 breaks the Next or Payload tooling | Pin `typescript@~5.9` (Phase 1.1) |
| Production schema changes by accident | `push` is on only outside production. Production applies committed migrations in `pnpm build` |
| Payload REST and app routes collide | App routes live under `/api/app/*` only |
| A `users` account reaches the admin panel or another user's bills | `users.access.admin = () => false`, `isOwnerOrAdmin` on bills, `overrideAccess: false` in every app route handler, and `normalizeBill` forces `user` |
| Bots find and attack the admin panel | Non-default `/bp-management` path, login lockout on `admins`, optional IP or Basic Auth middleware (1.6) |
| The admin path leaks | It's only a speed bump: rename the folder and `ADMIN_ROUTE`, then redeploy (1.6) |
| Duplicate products from two saves at once | Unique `normalizedKey` + a second lookup in `linkProducts` |
| Larger serverless bundle and slower cold starts | Import `@google/genai` only in `server/gemini.ts`, used only by the two AI routes |
| Users notice the forced logout | Announce the cutover window (5.5) |
